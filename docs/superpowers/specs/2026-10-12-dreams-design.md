# dreams 应用设计

日期：2026-10-12
所属 tap：`hub-apps`（公开仓库 `Jenwein/hub-apps`）
目标 cc-hub 版本：0.4.0 及以上

标注约定：没有标注的内容是用户的决定；标"（Claude 定）"的是 Claude 替用户做的选择，用户可以改；标"（留给实现者）"的由实现者决定。

---

## 1. 这是什么，为什么做

`dreams` 是 `hub-apps` 里的记梦应用。用户醒来后在聊天里把梦讲给 agent，agent 把梦记下来，按心理学的方法帮用户解梦，并且每月总结一次反复出现的主题和情绪变化。

这个应用公开发布，任何 cc-hub 用户都能装；梦的内容是每个用户自己的私人数据，只存在他自己的总站里。

解梦以心理学为主、结合用户最近的生活，而且要有一套固定的方法和规则，不能每次随口发挥：方法定了，同一个梦今天解和明天解走的是同一套步骤；标签定了，每月的统计才有可比性。

## 2. 目标、非目标、绝对不能出的错

**目标**

- 记梦：用户讲完（完整的或只有碎片），agent 存下原话，整理成一篇梦，打好标签。
- 解梦：用户愿意时当场按固定方法（§5）一起解；不愿意时先记下，事后写一份标明为猜测的初步解读，用户之后随时可以要求再解。
- 月度总结：每月一次，告诉用户反复出现的主题和情绪变化（§7）。
- 噩梦和普通的梦一样解，不做特殊处理。

**非目标**

- 语音转文字：交给 cc-connect（它自己的语音识别配置），应用不涉及，文档也不提。
- 解梦词典式的"梦见 X 代表 Y"。
- 心理治疗或医疗诊断；应用不提供噩梦治疗。
- 睡眠监测、清醒梦训练、早上提醒用户记梦（Claude 定：这次不做）。
- 读取其他应用的数据（例如记账）来解梦（Claude 定）。

**绝对不能出的错**

1. 把解读说成定论。解读一律是假设，最后由用户说了算；用户说不对就改。
2. 统计数字是编的或数错的。次数、比例、趋势都由脚本从标签算出来（§8），agent 只把结果写成人话。
3. 梦的内容去到用户的私聊和他自己的总站以外的地方：不在群聊里谈，不拿梦的内容去网上搜，不发到别处（Claude 定）。
4. 用解梦词典或固定象征表代替用户自己的联想。

## 3. 国际化

- 给 agent 读的文字（skill、`SETUP.md`、cron 提示词）用英文写；agent 跟用户说用户的语言。
- 整理后的梦、解读、主题词用用户的语言。
- 标签里的固定类别（§6）用统一的英文值，便于统计；主题词是用户语言的自由词。

## 4. 记梦

1. 用户在聊天里讲梦，可以是碎片。agent 先把原话原样存下。
2. agent 整理出：标题、经过、梦里的情绪和醒来时的情绪（各带强弱）、是否清醒梦、是否噩梦、做梦的日期（梦发生的那一夜，用户说"前天的梦"就记前天），并按 §6 打标签。
3. 一夜做了几个梦就记几篇。
4. 整理完问一句"现在聊聊，还是先休息？"。用户选休息就到此为止。
5. 写入后提交（只提交 `dreams/` 下的改动）。

用户不想当场聊时：agent 就在这一轮里写一份简短的"初步解读"存进这篇梦，只依据梦本身和用户最近的记录（§5 的"生活背景"），明确标为"没问过你的猜测"；回复用户时只说一句"记下了，休息吧"，不把初步解读发出来（Claude 定）。用户哪天说"解一下前天那个梦"，agent 先给他看初步解读，再按 §5 完整地解；完整解读写好后，初步解读保留但不再算数。月度总结只用用户确认过的解读和现实关联，不用初步解读（Claude 定）。

## 5. 解梦方法

以 Clara Hill 的认知-体验模型为骨架，借用荣格派的两点，所有结论都当作假设。

**一、探索**

- 挑出梦里两三个最鲜明的画面（人物、物件、场景、事件），逐个问：
  - 描述：再具体说说它是什么样的；
  - 重新体会：回到那个画面里，当时什么感觉；
  - 联想：它让你想到什么人、什么事、什么时候；
  - 现实触发：最近现实里有没有和它相关的事。
- 噩梦同样走完这四步。
- 对梦里出现的人，问一句：他是"现实里那个人"，还是更像"你自己的某一面"（荣格的客体层面和主体层面）。

**二、理解**

- 先问用户自己觉得这个梦是什么意思。
- 再结合用户的回答和生活背景，提出两到三种可能的解释，每种写清依据（来自用户的哪句联想、哪件现实的事）。
- 由用户挑、改或否定；用户的结论记为最终解读。

**三、行动**（可选）

- 问一句"这个梦让你想对现实做点什么吗"；没有就算了。
- 噩梦可以多一个可选练习：想不想给它换个结局。只在用户愿意时做。

**生活背景**

- 主要靠解梦时直接问用户（"现实触发"那一步）。
- 补充来源：总站里用户最近大约一周的记忆日志和 `USER.md`（Claude 定）。
- 只把这些当作待确认的猜测（"梦反映清醒时的牵挂"本身就是一个假说），不能当结论。

**系列**：解一个梦时，看一眼最近同主题的梦；反复出现本身就是线索（荣格：一连串的梦比单个梦可靠）。

**规则**

- 不用解梦词典，不说"X 象征 Y"这种固定对应。
- 不诊断、不当治疗。
- 噩梦本身不触发任何提醒。只有两种情况例外（Claude 定，用户可以去掉）：
  - 记录里出现睡梦中真的动手、喊叫、下床这类情况，agent 提一次"这可能是睡眠方面的问题，值得找医生看看"；
  - 用户在讲梦或聊天时表达出想伤害自己，agent 停下解梦，简短地建议他找信任的人或专业的人聊聊。这个应用是公开的，不能假设每个用户的情况。

解梦的问答和最终解读都存进这篇梦里，月度总结要用。

## 6. 标签

每篇梦按同一套规则打标签。规则写在 skill 里，以 Hall–Van de Castle 梦境内容编码体系的精简版为基础：

- **人物**：认识的人（记称呼）、陌生人、动物；
- **互动**：友好、冲突、亲密，以及谁先发起；
- **情绪**：梦里的情绪，取值固定为害怕、生气、难过、困惑、开心、其他六种，各记强弱（弱、中、强）。用户没主动说的，整理时问一句，因为情绪最容易漏报。醒来时的情绪另记一项，只存不统计（Claude 定）；
- **结果**：成功、失败、好运、倒霉；
- **场景**：熟悉或陌生、室内或室外，外加具体地点（自由词，例如"学校""老家"）（Claude 定）；
- **主题**：自由的主题词；
- **现实关联**：解梦时用户认可的现实事件，一句话。

`dreams/` 里有一份词表，分人物、地点、主题三部分，把指同一个人、同一个地方、同一个主题的不同说法归成一个（例如"妈妈""我妈""母亲"是同一个人，"被追"和"逃跑"都算"追赶"）（Claude 定）。agent 打标签时优先用表里已有的词，确实是新的才加，并写进词表。统计时一律按词表归并后计数。

## 7. 月度总结

每月 1 号 21:00 由定时任务生成上个月的总结，发到用户的私聊里，同时存成一篇文件。内容：

- **反复出现的主题**：这个月出现两次及以上的主题、人物、地点（按词表归并后）。和上个月比是多了还是少了；从没在以前的月份出现过的标为"新出现"。每条附上是哪几个梦（Claude 定）。
- **情绪变化**：每种情绪出现在这个月多少个梦里；按周的起伏；附一张最近 12 周按周的趋势图（用 `cc-connect send --image` 发送）（Claude 定）。
- **和现实的联系**：把这个月用户认可过的现实关联放在一起看。
- **口径**：
  - 占比 = 含有这种情绪的梦 ÷ 记了情绪的梦；没记情绪的梦不进分母（Claude 定）。
  - 用户累计记的梦不到 50 个时只说次数，不说百分比；到了 50 个以后才同时给出百分比（Claude 定）。
  - 比较只跟用户自己的历史比，不跟别人的常模比。
- 这个月没有记梦，就只发一句话。

## 8. 应用的组成

- **app.toml**：应用名 `dreams`，数据目录 `dreams`，依赖只有 `uv`（`min_hub = "0.4.0"`）。
- **数据目录**（Claude 定，具体文件名和格式留给实现者）：
  - 每个梦一篇 Markdown，按年份分目录，开头是标签区（YAML front matter），正文是原话、整理后的梦、解读和问答；
  - 主题词表；
  - 月度总结，每月一篇。
- **skill**：一个 `dreams` skill，`SKILL.md` 讲总规则（私聊、不出总站、解读是假设、写入后提交），细节拆到参考文件：记梦、解梦方法、标签规则、月度总结。拆分方式留给实现者。
- **统计脚本**：一个用 `uv run` 跑的小脚本（依赖写在脚本头部），从标签算出月度统计和趋势图；也负责平时的查询，按人物、地点、主题、情绪、时间段筛选并计数或列出梦（例如"最近梦到过几次考试"、解梦时"最近同主题的梦"），查询词先按词表归并，词表里没有时再在正文里搜（Claude 定）。agent 不自己数数。
- **定时任务**：只有一个 `monthly`，每月 1 号 21:00，`default: true`，`session: new_per_run`。正文不含反引号、`$`、引号和反斜杠（cc-hub 登记时会把正文放进双引号）。
- **SETUP.md**：不需要问用户任何设置，没有要另装的软件（Claude 定）。如果实现者认为需要（例如检查 uv 能不能跑脚本），只放检查步骤。
- **README**：在 tap 的 README 里加一节，说明这个应用做什么、怎么用。

## 9. 怎么用（README 底稿）

- 醒来在聊天里说"我做了个梦……"，讲完 agent 会记下来，问你要不要现在聊。
- 想解以前的梦，说"解一下前天那个梦"。
- 每月 1 号晚上收到上个月的梦境总结。
- 想看某段时间、某个主题的梦，直接问，比如"最近梦到过几次考试"。

## 10. 开发和测试

- 统计脚本有自动测试，用合成的梦境文件，覆盖次数、占比口径（累计 50 个梦以下只报次数）、按周的情绪起伏、词表归并、"新出现"和环比、查询筛选。
- skill 文字有一致性测试（链接有效、提到的脚本命令存在），沿用 `ledger` 的做法。
- 应用通过 cc-hub 实际安装一遍（沿用 `ledger` 的安装测试）。
