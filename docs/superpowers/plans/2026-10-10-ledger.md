# Ledger App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `ledger`, the first app of the `hub-apps` tap: a cc-hub app that lets the agent keep the user's books with beancount, import bills through double-entry-generator without double counting, answer questions, send charts, and run Fava.

**Architecture:** The app is mostly text for the agent (one skill with reference files, `SETUP.md`, `REMOVE.md`, two cron prompts) plus a seed ledger. Everything that must be exact runs in one Python CLI, `ledger/scripts/lk.py` (a PEP 723 script run with `uv run`), backed by the package `ledger/scripts/ledgerkit/`: `convert` wraps double-entry-generator, `match` decides new/duplicate/fix/uncertain for every staged entry, `apply` writes the decided plan, and every write is rolled back if beancount reports new errors. Tests live at the tap root, outside the app.

**Tech Stack:** Python ≥ 3.10, beancount 3.2 (library), PyYAML, matplotlib, openpyxl, xlrd, pdfplumber, pytest, ruff, uv; external tools double-entry-generator v2.16.0, Fava 1.30, cc-hub ≥ 0.4.0, cc-connect ≥ 1.5.

**Spec:** `docs/superpowers/specs/2026-10-10-ledger-design.md` (Chinese). Read it before any task. Platform docs: cc-hub `docs/apps.md` and the `hub-apps` skill (`C:\dev\cc-hub\src\cc_hub\templates\skills\hub-apps\`).

## Review Focus

1. **Bill encodings.** Alipay CSV is GBK, Meituan CSV is UTF-8 with BOM and CRLF, CCB `.xls` holds GBK strings. `table` must print readable text for each; `convert` must pass the original bytes to double-entry-generator untouched. Tests: Task 6 (`test_gbk_csv`, `test_bom_crlf_csv`), Task 3 (`test_convert_passes_original_file`).
2. **The same bill imported twice, or a plan applied twice.** Must not create a single extra entry. Tests: Task 4 (`test_reimport_is_all_duplicates`), Task 5 (`test_plan_applied_twice_is_refused`).
3. **Several identical amounts on one card and day** (two 20.00 rides). Each existing entry may be matched once. Test: Task 4 (`test_identical_amounts_match_one_to_one`).
4. **Non-ASCII and spaces in paths** (a bill named `交易明细 2026-09.xls` in a folder with spaces). Convert, table and the document copy must work. Tests: Task 3 (`test_convert_paths_with_spaces_and_chinese`), Task 5 (`test_document_with_chinese_name`).
5. **A batch spanning a year boundary, and a ledger that already has errors.** Entries go to both year files, the new year file is picked up by the include glob, and old errors don't block a clean write. Tests: Task 2 (`test_add_across_year_boundary`, `test_guarded_ignores_existing_errors`).

### Task 3: `lk convert` — double-entry-generator wrapper

**Files:**
- Create: `ledger/scripts/ledgerkit/convert.py`, `ledger/importers/alipay.yaml`, `ledger/importers/wechat.yaml`, `tests/test_convert.py`, `tests/fixtures/deb/` (copies + `NOTICE`)
- Modify: `cli.py` (subcommand `convert`)

**Interfaces:**
- Consumes: `Source`, `Settings`, `source()`, `LedgerError` (Task 1); `parse_text`, `format_entry`, `transactions`, `PLACEHOLDERS` (Task 2).
- Produces (`ledgerkit.convert`):
  - `NEVER = "__ledger_never_matches__"`
  - `build_config(src: Source, settings: Settings, defaults_dir: Path, ledger_dir: Path, account: str | None) -> dict`
  - `normalize(entries: list, via: str) -> list`
  - `closing_balance(entries: list, account: str, currency: str) -> Balance | None`
  - `convert(src: Source, bill: Path, out: Path, *, settings: Settings, defaults_dir: Path, ledger_dir: Path, account: str | None, deb: str = "double-entry-generator") -> dict` → `{"staged": str(out), "entries": n, "balance": "<balance directive text>" | None}`
- CLI: `lk convert --source NAME --file BILL --out STAGED --ledger-dir DIR [--account ACCOUNT]`. `defaults_dir` is `Path(lk.py).parent.parent / "importers"`.

Rules the code must follow:
- `build_config`: `{"title": "ledger", "defaultCurrency": settings.currency, "defaultMinusAccount": "Assets:Unmapped", "defaultPlusAccount": "Expenses:Unsorted", src.provider: {"rules": rules}}` where `rules` = the `rules` list of `defaults_dir/<name>.yaml` (if present) followed by the `rules` list of `ledger_dir/importers/<name>.yaml` (if present), because double-entry-generator lets the **last** matching rule win field by field. Bank sources (`kind == "bank"`) require `account` (`LedgerError("--account is required for bank statements")`), set `"defaultCashAccount": account`, and always append `{"peer": NEVER, "targetAccount": "Expenses:Unsorted"}` (the card account only applies when the bank's rule list is non-empty). A source with `provider is None` → `LedgerError("<name> has no converter; read the file with lk table")`.
- `convert`: writes the config with `yaml.safe_dump(..., allow_unicode=True)` to a temporary directory, runs `[deb, "translate", "-p", provider, "-t", "beancount", "--config", cfg, "-o", tmp_out, *extra_args, str(bill)]` (note: `--config` has no short form), passes the bill path untouched. Non-zero exit → `LedgerError` with stderr. Output parsed with `parse_text`; keep only transactions; zero transactions → `LedgerError("no transactions in <bill>; is it a <name> export?")`. Write `normalize(...)` entries (and the closing balance, if any) to `out` with `format_entry`.
- `normalize`: sets `via` meta on every transaction; replaces every posting account that has a component `FIXME` or is one of the default accounts above: `Assets:`/`Liabilities:` ones → `Assets:Unmapped`; others → `Expenses:Unsorted` when the units are positive, `Income:Unsorted` when negative; also moves a negative `Expenses:Unsorted` posting to `Income:Unsorted`.

### Task 4: `lk match` — new, duplicate, fix or uncertain

**Files:**
- Create: `ledger/scripts/ledgerkit/match.py`, `tests/test_match.py`
- Modify: `cli.py` (subcommand `match`)

**Interfaces:**
- Consumes: `Settings`, `source()` (Task 1); `load`, `parse_text`, `format_entry`, `transactions`, `funding_postings`, `is_transfer`, `PLACEHOLDERS` (Task 2).
- Produces (`ledgerkit.match`):
  - `@dataclass class Item: id: str; kind: str; reason: str; date: str; text: str; flags: list[str]; existing: list[dict]; fix: dict | None` — `kind` ∈ `new | duplicate | fix | uncertain`; `existing` items are `{"file": str, "line": int, "text": str}`; `fix` is `{"file", "line", "account_from", "account_to", "meta": {key: value}}`
  - `match(existing: list, staged: list, settings: Settings) -> list[Item]`
  - `run(main: Path, staged_path: Path, out: Path, settings: Settings) -> dict` — writes the plan, returns `{"plan": str(out), "new": n, "duplicate": n, "fix": n, "uncertain": n, "flagged": {"unsorted": n, "unmapped": n, "investment": n}}`
- Plan file (JSON, UTF-8): `{"version": 1, "ledger": "<main path>", "staged": "<staged path>", "applied": false, "items": [Item...], "balances": ["<balance directive text>", ...]}` — balances are the `Balance` directives found in the staged file.
- CLI: `lk match --ledger-dir DIR --staged STAGED --out PLAN`.

Algorithm. A staged transaction without `via` → `LedgerError("staged entry on <date> has no via")`. Staged transactions are taken in date order and get ids `s1, s2, …`. `window = settings.window_days`; "in window" means `abs((E.date - S.date).days) <= window`. An existing entry used by one item is never used again (`used` set). The kind of S comes from `source(settings, S.meta["via"]).kind`; S is a **channel line** when its kind is `bank` and its payee or narration contains any of `settings.channel_keywords`. First rule that applies wins:

1. **order-id** — S has `orderId` and an unused E has the same `via` and `orderId` (also checked against staged entries already seen in this run) → `duplicate`.
2. **chat** — candidates: unused E with `via == "chat"`, no `orderId`, in window, sharing a funding posting amount with S (`units` equal as Decimal, same currency), and either sharing the funding account or `E.meta.get("channel") == S.meta["via"]`. Keep those at the smallest date distance. One → `fix`: `account_from`/`account_to` are E's and S's funding accounts (equal when nothing changes), `meta` = S's `orderId`, `payTime` and `via` copied as `bill: <via>` (E keeps `via: "chat"`); several → `uncertain` (`chat`).
3. **posting** — candidates: unused E in window sharing a posting with S: same account (not a placeholder) and same `units`. Keep those at the smallest date distance, in file order.
   - S is a channel line, or the first candidate `is_transfer` → the first candidate makes S a `duplicate` (`channel` / `transfer`).
   - otherwise any candidate → `uncertain` (`possible-duplicate`).
4. **channel-unmatched** — S is a channel line with no candidate → `uncertain`.
5. **possible-chat** — an unused chat E (no `orderId`) in window with the same absolute funding amount but another account → `uncertain`.
6. otherwise `new`.

Flags on every item: `unsorted` (a posting on `Expenses:Unsorted` or `Income:Unsorted`), `unmapped` (on `Assets:Unmapped`), `investment` (payee or narration contains one of `settings.invest_keywords`).

### Task 5: `lk apply` — write a plan

**Files:**
- Create: `ledger/scripts/ledgerkit/apply.py`, `tests/test_apply.py`
- Modify: `cli.py` (subcommand `apply`; exit code 2 for `NeedsDecision`)

**Interfaces:**
- Consumes: `guarded`, `append_entries`, `parse_text`, `load`, `PLACEHOLDERS` (Task 2); the plan format (Task 4).
- Produces (`ledgerkit.apply`):
  - `class NeedsDecision(Exception)` with attribute `payload: dict` (`{"undecided": [ids]}` or `{"unresolved": [{"id", "flags"}]}`)
  - `apply_plan(plan_path: Path, ledger_dir: Path, decisions: dict[str, str], document: Path | None = None, document_account: str | None = None) -> dict` → `{"written": n, "skipped": n, "fixed": n, "balances": n, "document": "<path relative to ledger_dir>" | None}`
- CLI: `lk apply --ledger-dir DIR --plan PLAN [--decide ID=new|skip ...] [--document FILE --document-account ACCOUNT]`; `NeedsDecision` prints its payload as JSON and exits 2.

Rules:
- `plan["applied"]` true → `LedgerError("plan already applied")`.
- Every `uncertain` item needs a decision (`new` writes it, `skip` drops it); missing ones → `NeedsDecision({"undecided": [...]})`. A decision for an unknown id or with another value → `LedgerError`.
- Items to write (`new` plus `uncertain` decided `new`) whose flags include `unsorted` or `unmapped` → `NeedsDecision({"unresolved": [...]})`. Nothing is written in either case.
- A document account that is not opened in the ledger → `LedgerError` before writing.
- Inside one `guarded(ledger_dir)`: apply fixes per file from the bottom up: the line `fix.line` must start with the entry's date (else `LedgerError("ledger changed since match; run match again")`); within the entry block (that line plus the following indented lines) replace the account on the first posting line whose account is `account_from` with `account_to` (only when they differ; the line may have no amount, which beancount interpolates), and insert `  key: "value"` lines right after the header for keys not already present. Then `append_entries` the items to write and the plan's balances.
- After the guard succeeds: copy `document` to `ledger_dir/documents/<account components joined by />/<YYYY-MM-DD>.<original file name>` where the date is the latest item date in the plan (today if none); then set `"applied": true` and `"result": <summary>` in the plan file.
